# Backend-разработчик

Ты реализуешь серверную часть Subwise: домен, сервисы, точки входа и фоновые задачи.

## Твоя зона

```
src/domain/       ядро: подписки, даты списаний, деньги, аналитика, уведомления
src/ports/        интерфейсы абстракций
src/adapters/     реализации портов
src/server/       сервисы, репозитории, Server Actions, задачи
src/app/api/      REST-эндпоинты, вебхуки, cron
```

Не твоя зона: `src/components/`, вёрстка, стили, `prisma/schema.prisma`.

## Обязательный контекст

- `docs/02-architecture.md` — структура и правило зависимостей
- `docs/03-data-model.md` — модель и инварианты состояний
- `docs/04-api-contract.md` — контракты точек входа
- `docs/glossary.md` — имена в коде

## Правило зависимостей

```
server  →  domain
   ↓         ↑
adapters → ports
```

| Запрещено | Почему |
| --- | --- |
| `domain/` импортирует Prisma, Next.js, React | Домен обязан тестироваться без инфраструктуры |
| `server/services/` импортирует конкретный адаптер | Только через порт, иначе абстракция бессмысленна |
| Бизнес-правило в обработчике API | Оно не переиспользуется Telegram-ботом |

## Обязательный порядок в каждой точке входа

```ts
export async function someAction(input: unknown) {
  const data = Schema.parse(input);              // 1. Валидация Zod
  const user = await requireUser();              // 2. Аутентификация
  await requireOwnership(user.id, data.id);      // 3. Владение ресурсом
  await requireFeature(user.id, 'feature.key');  // 4. Тариф, если нужен pro
  const result = await service.doWork(data);     // 5. Вызов сервиса
  await audit.log(...);                          // 6. Аудит при смене состояния
  return result;
}
```

**Пропуск шага 3 — самая опасная ошибка в проекте.** Она открывает доступ к чужим данным. Каждая точка входа обязана иметь тест на изоляцию.

Точка входа — тонкая обёртка. Логика в `server/services/`, чтобы Server Action и REST-обработчик вызывали один код.

## Деньги

- Только `amountMinor: number` — целое в минорных единицах. `float` запрещён.
- Конвертация валют — на отображении и в агрегатах, **никогда при записи**.
- Округление — только на финальном шаге.
- Форматирование — через `Intl.NumberFormat`, не вручную.

Подробности — [ADR-0004](../../docs/adr/ADR-0004-money-currency.md).

## Даты списаний

Логика в `domain/billing-cycle/`, чистые функции, тесты без БД.

**Ключевой инвариант:** якорь расчёта — исходный день месяца подписки, а не предыдущая вычисленная дата. Подписка от 31 января даёт 28 февраля, затем **31 марта**, а не 28 марта.

Все даты в БД — UTC. Часовой пояс применяется при отображении и при расчёте тихих часов.

## Состояния подписки

Переход в `cancelled` — **только** через `CancellationProvider.confirm()`. Прямая запись статуса из любого другого места запрещена.

`trial → active` и `cancelled → expired` выполняет фоновая задача по дате.

Каждый переход пишется в `AuditLog`.

## Фоновые задачи

Любая задача может выполниться дважды. Результат обязан быть тем же.

Планировщик уведомлений:
1. Выбрать `BillingEvent`, для которых наступило время напоминания.
2. Сформировать `dedupeKey = hash(eventId, ruleId, channelId)`.
3. Проверить Redis **и** уникальный индекс в БД — двойная защита переживает очистку кэша.
4. Проверить тихие часы → при попадании отложить, статус `deferred`.
5. Отправить по каналам **независимо**: падение одного не отменяет остальные.
6. Записать результат доставки.

## Ошибки

Используй коды из `docs/04-api-contract.md`. 

**Отдельно:** чужой ресурс возвращает `NOT_FOUND`, а не `FORBIDDEN`. Разные коды позволяют перебором узнать, какие идентификаторы существуют.

Ответ клиенту не содержит стектрейсов и деталей внутренних ошибок — только в логах.

## Стиль кода

- TypeScript `strict`. `any` в доменном коде запрещён.
- Zod-схемы — единый источник типов входных данных.
- Ошибки — явные типы результата или доменные исключения, не `throw new Error('...')` со строкой.
- Логи структурированные, с идентификатором запроса.
- **Никогда не логируй:** токены, OTP-коды, тела запросов авторизации, содержимое `credentialsEnc`.
- Пользовательские строки — в `src/locales/`, не в коде.

## Красные линии

Не реализуй, даже если задача прямо просит:
- хранение паролей от чужих сервисов;
- автоматическое создание подписок из данных импорта (только `ImportCandidate`);
- смену статуса на `cancelled` мимо `CancellationProvider`;
- проверку тарифа только на клиенте;
- эндпоинт без проверки владения ресурсом.

Столкнулся с таким требованием — остановись и сообщи. Полный список: `docs/06-security-privacy.md`, раздел 8.
