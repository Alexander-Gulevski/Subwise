# 04. Контракты API

> Статус: черновик на согласовании · Обновлён: 2026-07-27

## 1. Два вида точек входа

| Вид | Когда используется | Где лежит |
| --- | --- | --- |
| **Server Actions** | Мутации из веб-интерфейса: создать, изменить, отменить | `src/server/actions/` |
| **REST API** | Всё, что вызывается извне: Telegram-бот, Mini App, cron, вебхуки | `src/app/api/` |

**Почему так:** веб-интерфейс не нуждается в HTTP-слое — Server Actions дают типобезопасность от формы до базы. Но Telegram-бот и Mini App — внешние клиенты, им нужен явный контракт.

**Общее правило:** и Server Action, и REST-обработчик — только тонкая обёртка. Вся логика в `server/services/`, чтобы обе точки входа вызывали один и тот же код.

## 2. Обязательный порядок в каждой точке входа

```ts
export async function someAction(input: unknown) {
  const data = Schema.parse(input);              // 1. Валидация через Zod
  const user = await requireUser();              // 2. Аутентификация
  await requireOwnership(user.id, data.id);      // 3. Владение ресурсом
  await requireFeature(user.id, 'feature.key');  // 4. Тариф (если нужен pro)
  const result = await service.doWork(data);     // 5. Вызов сервиса
  await audit.log(...);                          // 6. Аудит, если меняется состояние
  return result;
}
```

Пропуск шага 3 — самая опасная ошибка в проекте: она даёт доступ к чужим данным. Проверяется на ревью и покрывается тестом на каждый эндпоинт.

## 3. Формат ответа REST

**Успех:**
```json
{ "ok": true, "data": { } }
```

**Ошибка:**
```json
{
  "ok": false,
  "error": {
    "code": "SUBSCRIPTION_NOT_FOUND",
    "message": "Подписка не найдена",
    "details": { }
  }
}
```

### Коды ошибок

| Код | HTTP | Когда |
| --- | --- | --- |
| `UNAUTHENTICATED` | 401 | Нет сессии или истекла |
| `FORBIDDEN` | 403 | Ресурс принадлежит другому пользователю |
| `PLAN_REQUIRED` | 402 | Функция требует тарифа `pro` |
| `LIMIT_EXCEEDED` | 409 | Превышен лимит бесплатного тарифа (10 подписок) |
| `VALIDATION_FAILED` | 422 | Не прошла Zod-схема, `details` содержит поля |
| `NOT_FOUND` | 404 | Ресурс не существует |
| `RATE_LIMITED` | 429 | Слишком много запросов, есть заголовок `Retry-After` |
| `PROVIDER_UNAVAILABLE` | 503 | Провайдер не настроен (нет токена бота, не задан SMTP). Проблема на нашей стороне, а не в запросе |
| `INTERNAL` | 500 | Непредвиденная ошибка. Детали только в логах, не в ответе |

**Про `PROVIDER_UNAVAILABLE`:** отдельный код нужен, чтобы ошибка конфигурации не пряталась за общей 500-й. Клиент по нему понимает, что способ входа временно недоступен, и может предложить другой — а не показывать «что-то пошло не так».

**Важно:** `FORBIDDEN` и `NOT_FOUND` для чужих ресурсов возвращают **одинаковый** `NOT_FOUND`. Иначе по коду ответа можно перебором узнать, какие идентификаторы существуют.

## 4. Server Actions

### Подписки

| Действие | Вход | Результат | Примечания |
| --- | --- | --- | --- |
| `createSubscription` | сервис или своё название, сумма, валюта, период, дата | `Subscription` | Проверяет лимит `free` (10 шт.). Создаёт первый `BillingEvent` |
| `updateSubscription` | id + изменяемые поля | `Subscription` | При смене периода или даты пересчитывает будущие `BillingEvent` |
| `pauseSubscription` | id | `Subscription` | `active → paused`. Будущие события → `skipped`, напоминания молчат |
| `resumeSubscription` | id | `Subscription` | `paused → active`. Пересчитывает `nextBillingAt` от сегодня |
| `deleteSubscription` | id | `{ ok }` | Мягкое удаление, 30 дней на восстановление |
| `restoreSubscription` | id | `Subscription` | Только если `deletedAt` не старше 30 дней |
| `confirmCharge` | id события, факт | `BillingEvent` | Пользователь подтверждает списание. Повышает точность прогнозов |

### Отмена

| Действие | Вход | Результат |
| --- | --- | --- |
| `startCancellation` | id подписки | `CancellationFlow` + шаги гида + `deepLink` + предупреждения |
| `confirmCancellation` | id потока, исход, заметка | `CancellationResult` |

**Исходы `confirmCancellation`:**

| Исход | Что происходит |
| --- | --- |
| `succeeded` | Подписка → `cancelled`, фиксируется `accessUntil`, запись в `AuditLog` |
| `failed` | Состояние не меняется, предлагаются альтернативы: пауза или напоминание |
| `postponed` | Поток закрывается, создаётся напоминание вернуться |
| `guide_outdated` | `reportCount++` у гида, сигнал в очередь актуализации, состояние не меняется |

> **Инвариант:** это **единственный** путь перевода подписки в `cancelled`. Прямая запись статуса из других мест запрещена и проверяется на ревью.

### Настройки и уведомления

| Действие | Вход | Результат |
| --- | --- | --- |
| `updateSettings` | базовая валюта, локаль, часовой пояс, тихие часы | `UserSettings` |
| `upsertReminderRule` | тип, offsetDays, каналы | `ReminderRule` |
| `deleteReminderRule` | id | `{ ok }` |
| `markNotificationRead` | id доставки | `{ ok }` |
| `subscribeWebPush` | подписка Push API | `{ ok }` |

### Данные и тариф

| Действие | Тариф | Результат |
| --- | --- | --- |
| `exportUserData` | `pro` | Ссылка на выгрузку JSON и CSV (`FR-12`) |
| `requestAccountDeletion` | любой | Ставит `deletedAt`, стирание через 30 дней. Доступно всем — юридическое требование |
| `startImport` | `pro` | `ImportConnection` |
| `resolveImportCandidate` | `pro` | `accept` создаёт подписку, `reject` исключает кандидата навсегда |

## 5. REST API

### Публичное (без авторизации, для SEO)

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/catalog/services` | Список сервисов. Параметры: `q`, `category`, `limit`, `cursor` |
| `GET` | `/api/catalog/services/:slug` | Сервис с тарифами и гидом отмены |
| `GET` | `/api/catalog/categories` | Справочник категорий |

Кэшируются на CDN. Персональных данных не содержат. Rate limit по IP.

### Авторизация

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/auth/email/request` | Запросить OTP. Лимит: 3 за 15 минут на email и на IP |
| `POST` | `/api/auth/email/verify` | Проверить код. 6 цифр, 10 минут, максимум 5 попыток |
| `POST` | `/api/auth/telegram` | Вход по данным Telegram Login Widget |
| `POST` | `/api/auth/logout` | Завершить текущую сессию |
| `POST` | `/api/auth/logout-all` | Отозвать все сессии пользователя |

**Обязательно:** подпись данных Telegram проверяется через HMAC-SHA256 с токеном бота. Без проверки подписи вход подделывается тривиально.

**Обязательно:** ответ `/api/auth/email/request` **одинаков** независимо от того, существует ли аккаунт. Иначе endpoint превращается в проверку существования email.

### Клиентское API (Telegram-бот и Mini App)

Авторизация: `Authorization: Bearer <session token>`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/api/subscriptions` | Список. Фильтры: `status`, `upcoming` |
| `GET` | `/api/subscriptions/:id` | Одна подписка |
| `GET` | `/api/dashboard` | Сводка: итоги месяца и года, ближайшие списания, триалы |
| `GET` | `/api/analytics` | Аналитика. Параметр `range`. Глубже 3 месяцев — только `pro` |
| `GET` | `/api/notifications` | In-app лента за 90 дней |

### Вебхуки и служебное

| Метод | Путь | Защита |
| --- | --- | --- |
| `POST` | `/api/webhooks/telegram` | Секретный путь + `X-Telegram-Bot-Api-Secret-Token` |
| `POST` | `/api/cron/scheduler` | Заголовок `X-Cron-Secret`, сверка с переменной окружения |
| `POST` | `/api/cron/exchange-rates` | То же. Загрузка курсов ЦБ РФ раз в сутки |
| `POST` | `/api/webhooks/billing` | Зарезервировано под YooKassa, в MVP возвращает 501 |

**Все служебные эндпоинты обязаны:**
- отклонять запрос без валидного секрета кодом 401 без объяснений;
- быть идемпотентными — повторный вызов не должен создавать дубли (`NFR-05`);
- логировать факт вызова в структурированный лог.

## 6. Формат данных в ответах

### Деньги

Всегда объектом, никогда числом с плавающей точкой:

```json
{
  "amount": { "minor": 39900, "currency": "RUB" },
  "converted": { "minor": 39900, "currency": "RUB", "rateDate": "2026-07-27", "isStale": false }
}
```

- `minor` — целое число копеек.
- `converted` появляется, только если валюта подписки отличается от базовой.
- `isStale: true` означает, что свежий курс недоступен и взят последний известный (`NFR-05`). Интерфейс обязан это показать.

### Даты

ISO 8601 в UTC: `"2026-08-15T00:00:00.000Z"`. Перевод в часовой пояс пользователя — задача клиента.

### Пагинация

Курсорная, не по смещению:

```json
{ "items": [], "nextCursor": "cuid_abc", "hasMore": true }
```

Смещение (`offset`) даёт дубли и пропуски при вставке новых записей во время листания.

## 7. Ограничение частоты запросов

| Группа эндпоинтов | Лимит |
| --- | --- |
| `POST /api/auth/*` | 5 запросов / 15 мин на IP; 3 / 15 мин на идентификатор |
| Публичный каталог | 60 запросов / мин на IP |
| Клиентское API | 120 запросов / мин на пользователя |
| Импорт и сканирование | 10 запросов / час на пользователя |

Хранилище счётчиков — Redis. При превышении — `429` и заголовок `Retry-After`.

## 8. Версионирование

MVP работает без версии в пути. При первом ломающем изменении вводится `/api/v2/`, а `/api/*` замораживается минимум на 6 месяцев — у Telegram-бота могут быть старые клиенты.

**Что считается ломающим:** удаление поля, смена типа поля, ужесточение валидации, изменение семантики существующего кода ошибки. Добавление необязательного поля ломающим не является.
