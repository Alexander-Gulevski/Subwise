# ADR-0001: Next.js + TypeScript + PostgreSQL как основной стек

## Статус
Принято · 2026-07-27

## Контекст

- Первая платформа — веб-приложение PWA, вторая — Telegram-бот и Mini App.
- Разработку ведёт один исполнитель, поэтому цена лишней сложности высока.
- Домен насыщен деньгами, датами и состояниями — ошибки типизации дорого стоят.
- Нужны транзакции и точная арифметика: подписки, списания, курсы валют.
- Развёртывание — российская инфраструктура, без привязки к конкретному облаку.

Ключевое наблюдение: **Telegram Mini App — это веб-приложение внутри Telegram.** Вторая платформа не требует второго клиента, если первый сделан правильно.

## Решение

Мы используем:

| Слой | Технология |
| --- | --- |
| Фреймворк | Next.js 15, App Router |
| Язык | TypeScript, `strict: true` |
| БД | PostgreSQL 16 |
| ORM | Prisma |
| Кэш, очереди, лимиты | Redis |
| Фоновые задачи | BullMQ |
| UI | Tailwind CSS + Radix UI |
| Валидация | Zod |

## Альтернативы

**React + отдельный backend (NestJS).**
Чище разделение и удобнее для команды. Отклонено: для одного исполнителя удваивает объём инфраструктурного кода, дублирует типы на границе и замедляет каждое изменение. Разделение слоёв достигается структурой папок и линтером, а не отдельным процессом.

**React + Python (FastAPI).**
Сильно, если во главе угла ML и парсинг выписок. Отклонено: парсинг — это M3+, а два языка в проекте платятся с первого дня. При необходимости распознавание выносится отдельным сервисом позже.

**PostgreSQL → MongoDB.**
Отклонено: домен реляционный по природе (пользователь → подписка → события списаний), а денежные агрегаты требуют транзакций и точной арифметики.

**Prisma → Drizzle.**
Drizzle ближе к SQL и легче. Отклонено на старте: у Prisma лучше миграции и генерация типов, а это важнее для одиночной разработки. Пересмотрим, если упрёмся в производительность запросов.

**Tailwind + Radix → готовая библиотека компонентов.**
Отклонено: доступность (`NFR-02`) — требование, а не украшение. Radix даёт корректные примитивы, поверх которых строится своя дизайн-система, без борьбы с чужими стилями.

## Последствия

**Стало проще:**
- Один язык и один репозиторий на всё.
- Telegram Mini App переиспользует веб-интерфейс — вторая платформа почти бесплатна.
- Типы от схемы БД до React-компонента без ручной синхронизации.
- Server Actions убирают HTTP-слой там, где он не нужен.

**Стало сложнее:**
- Легко случайно смешать серверный и клиентский код. Лечится строгими границами слоёв в линтере.
- Next.js быстро меняется — потребуется дисциплина обновлений.

**Теперь запрещено:**
- Импорты Prisma, Next.js и React в `domain/`.
- Прямые обращения к БД из компонентов.
- `any` в доменном коде.

## Когда пересмотреть

- Появилось нативное мобильное приложение и веб-клиент перестал быть основным потребителем API.
- Аналитика перестала укладываться в PostgreSQL — потребуется отдельное хранилище.
- Планировщик перерос BullMQ по объёму задач.
