# ADR-0002: Гибридная отмена — гиды сейчас, автоматизация за интерфейсом

## Статус
Принято · 2026-07-27

> Это центральное продуктовое и архитектурное решение проекта.

## Контекст

Обещание «отменить подписку в один клик» — главная ценность категории. Но техническая реальность жёсткая:

- У Netflix, Spotify, Apple, Google, Яндекса **нет публичного API для отмены подписки** сторонним приложением.
- Автоматизация возможна тремя путями, и каждый имеет цену:
  1. **Виртуальные карты** — заморозка карты вместо отмены. Требует партнёрства с эмитентом и лицензий.
  2. **Логин от имени пользователя** (путь Rocket Money) — требует хранения чужих паролей и нарушает пользовательские соглашения большинства сервисов.
  3. **Официальные партнёрства** — годы переговоров, недоступно на старте.
- Главный репутационный риск категории: пользователь уверен, что подписка отменена, а списание проходит. Одного такого случая достаточно, чтобы потерять доверие навсегда.

## Решение

**Продуктово:** в MVP отмена реализуется как пошаговый гид. Пользователь отменяет сам, приложение приводит его точно в нужное место и фиксирует результат с его слов.

**Архитектурно:** отмена всегда проходит через порт `CancellationProvider`. В MVP у него одна реализация — `GuideCancellationProvider`. Экраны и сервисы не знают, что стоит за интерфейсом.

```ts
interface CancellationProvider {
  readonly kind: 'guide' | 'virtual-card' | 'automated';
  supports(service: Service): boolean;
  start(subscription: Subscription): Promise<CancellationFlow>;
  confirm(flowId: string, outcome: CancellationOutcome): Promise<CancellationResult>;
}
```

**Инвариант:** подписка переходит в статус `cancelled` **только** через `confirm()`. Прямая запись статуса из любого другого места запрещена и проверяется на ревью.

Интерфейс никогда не утверждает, что подписка отменена, без явного подтверждения пользователя.

## Альтернативы

**Обещать автоматическую отмену сразу.**
Отклонено. Требует хранения чужих паролей — прямое нарушение красных линий из [06-security-privacy.md](../06-security-privacy.md). Плюс нарушение ToS сервисов и хрупкость: любое изменение вёрстки ломает автоматизацию молча, и пользователь узнаёт об этом из списания.

**Виртуальные карты с первого дня.**
Отклонено на старте. Решение рабочее и, вероятно, правильное в перспективе, но требует партнёрства с эмитентом и лицензий — это месяцы до первой строчки пользовательской ценности. Порт оставлен под него: `kind: 'virtual-card'`.

**Только гиды, без абстракции.**
Отклонено. Экономит немного кода сейчас и означает переписывание всего флоу отмены позже. Порт стоит примерно один файл.

**Не заниматься отменой вообще, только учёт.**
Отклонено: тогда продукт — красивая таблица. Отмена и есть момент, ради которого пользователь возвращается.

## Последствия

**Стало проще:**
- MVP реализуем без юридических и партнёрских блокеров.
- Отсутствует риск ложного «отменено» — статус меняет только пользователь.
- Гиды дают побочный эффект: публичные SEO-страницы «как отписаться от X» — основной канал органического роста.

**Стало сложнее:**
- Требуется ручное наполнение и поддержка каталога гидов. Гиды устаревают — отсюда поле `checkedAt` и кнопка «инструкция не сработала».
- Обещание в маркетинге слабее, чем у конкурентов с автоотменой. Компенсируется честностью, которая в этой категории — актив.

**Теперь запрещено:**
- Менять статус на `cancelled` вне `CancellationProvider.confirm()`.
- Показывать «отменено» до подтверждения пользователем.
- Скрывать предупреждение о сохранении доступа до конца оплаченного периода.

## Когда пересмотреть

- Найден способ автоматизации без хранения чужих учётных данных.
- Появился партнёр-эмитент для виртуальных карт.
- Крупный сервис открыл официальный API отмены.
- Метрика «дошли от напоминания до открытия гида» стабильно ниже 10% — значит, гиды не работают как механика, и нужен другой подход.
