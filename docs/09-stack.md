Обоснование ключевых решений — [ADR-0001](adr/ADR-0001-stack.md) и [ADR-0006](adr/ADR-0006-hosting.md). Здесь — полная карта: что стоит, зачем, где применяется.

## 1. Среда выполнения

| Компонент | Версия | Примечание |
| --- | --- | --- |
| Node.js | **24.12.0** | Зафиксирована в `.nvmrc`. Минимум в `package.json` — `>=20.11.0` |
| npm | 11.6.2 | Идёт с Node |
| nvm-windows | — | Менеджер версий. Глобальный Node системы **не переключается** |

**Как это работает на машине разработчика.** В системе может стоять другой Node (например, 14 для старых проектов). Скрипт `scripts/dev.cmd` читает `.nvmrc`, находит нужную версию в `%NVM_HOME%` и подставляет её в `PATH` только для своего процесса. Глобальный симлинк nvm не трогается — соседние проекты продолжают работать на своих версиях.

## 2. Приложение

### Ядро

| Пакет | Версия | Роль |
| --- | --- | --- |
| `next` | 15.5.22 | Фреймворк: маршрутизация, серверный рендеринг, Server Actions, API-роуты |
| `react` | 19.2.8 | UI |
| `react-dom` | 19.2.8 | Рендеринг в DOM |
| `typescript` | 5.9.3 | Типы. Режим `strict`, плюс `noUncheckedIndexedAccess` |

**Почему один Next.js вместо связки «фронт + отдельный бэкенд»:** Telegram Mini App — это веб-приложение внутри Telegram. Вторая платформа переиспользует тот же код, а не требует второго клиента. Для одного исполнителя разделение на два процесса удвоило бы инфраструктурный код без выигрыша.

### Данные

| Пакет | Версия | Роль |
| --- | --- | --- |
| `prisma` | 6.19.3 | CLI: миграции, генерация клиента, `prisma studio` |
| `@prisma/client` | 6.19.3 | Типобезопасный доступ к БД |
| `ioredis` | 5.11.1 | Клиент Redis: rate limiting, кэш курсов, дедупликация уведомлений |

Схема — [prisma/schema.prisma](../prisma/schema.prisma), описание — [03-data-model.md](03-data-model.md).

### Фоновые задачи

| Пакет | Версия | Роль |
| --- | --- | --- |
| `bullmq` | 5.81.2 | Очереди и планировщик на Redis |
| `tsx` | 4.23.1 | Запуск TypeScript напрямую: воркер, сид-скрипты |

Воркер — **отдельный процесс** (`npm run worker`), а не поток внутри приложения: тяжёлая фоновая задача не должна блокировать запросы пользователей. На M0 это заглушка; полноценный планировщик приходит на M2.

**Radix UI** — доступные примитивы. Доступность (`NFR-02`) это требование, а не украшение: корректные диалог, меню и селект сложнее, чем кажутся, и писать их заново — значит писать их с ошибками.

| Пакет | Версия | Где используется |
| --- | --- | --- |
| `@radix-ui/react-slot` | 1.3.3 | `Button` с `asChild` |

Остальные примитивы Radix (диалог, меню, селект, переключатель, вкладки, тосты) **не установлены**: ставим по одному, когда конкретный компонент их потребует. Восемь пакетов «на будущее» — это восемь зависимостей в `npm audit` без единой строчки пользы.

### Прикладное

| Пакет | Версия | Роль |
| --- | --- | --- |
| `zod` | 3.25.76 | Валидация. Одна схема даёт и проверку, и тип |
| `nodemailer` | 6.10.1 | Отправка писем с кодами входа |

**Про Zod.** Граница доверия — всегда сервер. Каждая точка входа начинается с `Schema.parse(input)`; тип выводится из схемы, поэтому расхождение между проверкой и типом невозможно по построению.

## 3. Инфраструктура

| Компонент | Версия | Роль |
| --- | --- | --- |
| PostgreSQL | 16-alpine | Основная БД |
| Redis | 7-alpine | Кэш, очереди, счётчики rate limiting |
| Docker Engine | 29.6.2 | Контейнеры |
| Docker Compose | 5.3.1 | Оркестрация локально и на VPS |

Состав `docker-compose.yml`: `app`, `worker`, `postgres`, `redis`. Один и тот же файл поднимает окружение локально и на российском VPS — площадка выбирается позже без изменений в коде ([ADR-0006](adr/ADR-0006-hosting.md)).

**Почему PostgreSQL, а не что-то другое:** домен реляционный по природе (пользователь → подписка → события списаний), денежные агрегаты требуют транзакций, а аналитика — оконных функций.

## 4. Разработка и качество

### Тесты

| Пакет | Версия | Роль |
| --- | --- | --- |
| `vitest` | 2.1.9 | Юнит- и интеграционные тесты |
| `@vitejs/plugin-react` | 4.7.0 | Поддержка JSX в тестах |
| `@testing-library/react` | 16.3.2 | Тесты компонентов по роли и тексту |
| `@testing-library/jest-dom` | 6.9.1 | Матчеры для DOM |
| `@testing-library/user-event` | 14.6.1 | Имитация действий пользователя |
| `jsdom` | 26.1.0 | DOM для компонентных тестов |
| `@playwright/test` | 1.62.0 | Сквозные тесты, проекты `chromium` и `mobile-chrome` |

**Правило:** тесты не ходят в сеть. ЦБ РФ, Telegram и SMTP всегда замоканы.

**Мокаем внедрением зависимости, а не перехватом HTTP.** Источник курсов подменяется через `setExchangeRateSource`, хранилище кодов — через порт `OtpStore`. Это проще библиотеки вроде MSW и заодно проверяет, что абстракции действительно работают: если порт нельзя подменить в тесте, он плохо спроектирован.

В тестах используется настоящая PostgreSQL, а не SQLite — различия в типах и часовых поясах пропустили бы ровно те баги, которые мы ловим.

Текущее состояние: **175 юнит- и интеграционных тестов, 100 сквозных прогонов**.

### Линт и типы

| Пакет | Версия | Роль |
| --- | --- | --- |
| `eslint` | 8.57.1 | Линтер |
| `eslint-config-next` | 15.5.22 | Правила Next.js |
| `@typescript-eslint/parser` | 8.65.0 | Разбор TypeScript |
| `@typescript-eslint/eslint-plugin` | 8.65.0 | Правила TypeScript |
| `eslint-plugin-boundaries` | 5.4.0 | **Границы слоёв архитектуры** |

**`eslint-plugin-boundaries` — не косметика.** Он машинно проверяет правило зависимостей из [02-architecture.md](02-architecture.md):

```
app / components  →  server  →  domain
                        ↓          ↑
                    adapters  →  ports
```

На первом же прогоне он поймал реальное нарушение: адаптер авторизации импортировал из `server/`. Правило не ослабили — переработали код.

Дополнительные запреты, встроенные в конфиг:

| Запрет | Причина |
| --- | --- |
| `$queryRawUnsafe` | SQL-инъекция (T12) |
| `dangerouslySetInnerHTML` | XSS (T6) |
| Импорты Prisma, Next.js, React в `domain/` | Домен обязан тестироваться без инфраструктуры |
| Импорт Prisma в компонентах | Доступ к данным только через `server/` |
| `any` в коде | Домен с деньгами и датами не прощает нетипизированного |

## 5. Что какому слою служит

| Слой | Технологии |
| --- | --- |
| `domain/` | Только TypeScript. **Ни одной зависимости** — это и делает домен тестируемым без БД и браузера |
| `ports/` | TypeScript + типы из `domain/` |
| `adapters/` | `nodemailer`, `node:crypto`, `zod`, `ioredis` |
| `server/` | `@prisma/client`, `bullmq`, Next.js Server Actions |
| `app/` | Next.js App Router |
| `components/` | React, Radix UI, Tailwind |
| `lib/` | `zod`, `ioredis`, `node:crypto`, `clsx`, `tailwind-merge` |
| `locales/` | Только TypeScript |

Отсутствие зависимостей у `domain/` — не случайность, а проверяемое линтером правило. Именно поэтому 45 доменных тестов выполняются за доли секунды и не требуют поднятой базы.

## 6. Команды

Локальное окружение:

```bash
docker compose up -d postgres redis
```

Установка и подготовка базы:

```bash
npm install && npx prisma migrate dev && npm run db:seed
```

Запуск:

```bash
npm run dev
```

Полная проверка перед коммитом:

```bash
npm run check
```

Полный список скриптов — в [package.json](../package.json): `dev`, `build`, `start`, `worker`, `typecheck`, `lint`, `test`, `test:e2e`, `check`, `db:generate`, `db:migrate`, `db:deploy`, `db:seed`, `db:studio`, `db:reset`.

## 7. Политика версий

| Правило | Причина |
| --- | --- |
| Версия Node зафиксирована в `.nvmrc` | Расхождение версий даёт ошибки, которые воспроизводятся только у одного разработчика |
| `package-lock.json` коммитится | CI и продакшн должны собираться из тех же версий |
| В CI — `npm ci`, не `npm install` | Ставит строго по локу |
| Мажорные обновления — отдельным PR | Их нужно смотреть отдельно от продуктовых изменений |
| `npm audit --audit-level=high` в CI | Уязвимость в зависимости — тоже уязвимость продукта |

## 8. Чего в стеке нет и почему

| Технология | Почему не взяли |
| --- | --- |
| Отдельный backend (NestJS, FastAPI) | Для одного исполнителя удваивает инфраструктурный код. Разделение слоёв достигается структурой папок и линтером, а не отдельным процессом |
| MongoDB и другие документные БД | Домен реляционный, денежные агрегаты требуют транзакций |
| Библиотека UI-компонентов целиком (MUI, Ant) | Борьба с чужими стилями дороже, чем сборка своих поверх доступных примитивов Radix |
| Redux, Zustand и прочий глобальный стор | Серверные компоненты Next.js покрывают потребность. Стор добавим, когда появится состояние, которое действительно глобально |
| Auth0, Clerk и внешние сервисы авторизации | Персональные данные граждан РФ уехали бы за рубеж — конфликт со 152-ФЗ. Плюс внешняя зависимость в самой критичной точке продукта |
| ORM с `Decimal` для денег | Целые минорные единицы дают ту же точность при более простой арифметике ([ADR-0004](adr/ADR-0004-money-currency.md)) |
| Kubernetes | Нагрузки, оправдывающей его, нет и в ближайшее время не будет |
| SQLite в тестах | Отличается от продакшн-БД типами и часовыми поясами — пропустил бы целевые баги |
| Сторонние аналитические трекеры | Приватность (`NFR-04`). Аналитика собственная и обезличенная |
