# 01. Требования

> Статус: черновик на согласовании · Обновлён: 2026-07-27

Термины, помеченные `курсивом при первом упоминании`, определены в [glossary.md](glossary.md).

## Как читать этот документ

- **ID требования** (`FR-01`, `NFR-03`) используется в коде, тестах и коммитах. Тест без ссылки на ID — повод задать вопрос.
- **Приоритет** по MoSCoW: `MUST` — без этого нет релиза, `SHOULD` — очень желательно, `COULD` — если останется время, `WONT` — явно вне текущей версии.
- **Критерии приёмки** написаны так, чтобы по ним можно было написать тест, не додумывая.

## Часть I. Функциональные требования

### FR-01. Учёт подписок вручную · MUST

Пользователь добавляет подписку, выбирая сервис из каталога или создавая свой.

**Поля подписки:**

| Поле | Обяз. | Примечание |
| --- | --- | --- |
| Сервис | да | Из каталога или произвольное название |
| Сумма | да | Число > 0 |
| Валюта | да | По умолчанию — базовая валюта пользователя |
| Период | да | Неделя / месяц / квартал / полугодие / год / произвольное число дней |
| Дата следующего списания | да | Не в прошлом при создании |
| Категория | нет | Из справочника, либо своя |
| Способ оплаты | нет | Свободный текст-метка («Тинькофф •4321»). **Номера карт не хранятся** |
| Заметка | нет | До 500 символов |

**Критерии приёмки:**
- Добавление подписки из каталога занимает не более 3 действий: выбрать сервис → подтвердить подставленный тариф → сохранить.
- При выборе сервиса из каталога сумма, период и категория подставляются автоматически и остаются редактируемыми.
- Дата следующего списания пересчитывается автоматически после наступления даты списания.
- Подписка может быть в одном из состояний: `active`, `paused`, `cancelled`, `trial`, `expired`.
- Удаление подписки — мягкое (`deletedAt`), с возможностью восстановления в течение 30 дней.

### FR-02. Единый обзор («Дашборд») · MUST

Главный экран отвечает на три вопроса за 5 секунд: сколько я плачу, что спишут ближайшим, где утечка.

**Критерии приёмки:**
- Отображается суммарный расход за месяц и за год в *базовой валюте*, с пересчётом по актуальному курсу.
- Блок «Ближайшие списания» показывает подписки на 30 дней вперёд, отсортированные по дате.
- Подписки в состоянии `trial` с окончанием ≤ 7 дней визуально выделены как приоритетные.
- Пустое состояние (0 подписок) предлагает добавить первую подписку из каталога, а не показывает пустой список.
- Дашборд рендерится за ≤ 1.5 с при 50 подписках (см. `NFR-01`).

### FR-03. Отмена и пауза подписки · MUST

Реализуется через *провайдер отмены* — абстракцию, у которой в MVP одна реализация.

**Реализация в MVP — `GuideCancellationProvider`:**
- Пошаговая инструкция отмены для конкретного сервиса из каталога.
- Прямая ссылка (deep link) в раздел управления подпиской на стороне сервиса.
- Предупреждение о том, что доступ обычно сохраняется до конца оплаченного периода.
- После прохождения гида — вопрос «Получилось отменить?» с вариантами `да` / `нет` / `позже`.

**Критерии приёмки:**
- Ответ `да` переводит подписку в `cancelled` и фиксирует дату окончания доступа.
- Ответ `нет` предлагает альтернативы: приостановить учёт, поставить напоминание, сообщить об устаревшей инструкции.
- «Пауза» (`paused`) останавливает напоминания и исключает подписку из расчёта расходов, но сохраняет её в списке.
- Для сервиса без гида показывается общая инструкция и поиск по названию, а не пустой экран.
- Интерфейс **никогда не утверждает, что подписка отменена**, без подтверждения пользователя.

> **Архитектурное требование:** отмена вызывается только через интерфейс `CancellationProvider`. Экраны не знают, гид это или будущая автоматизация. См. [ADR-0002](adr/ADR-0002-hybrid-cancellation.md).

### FR-04. Каталог сервисов · MUST

Справочник популярных в РФ и СНГ сервисов: логотип, категория, типовые тарифы, инструкция отмены.

**Критерии приёмки:**
- Поиск по названию работает с опечатками и по латинице для кириллических названий (`kinopoisk` находит «Кинопоиск»).
- Каждый гид содержит дату последней проверки. Гид старше 180 дней помечается как «требует проверки».
- Есть кнопка «Инструкция не сработала» — сигнал попадает в очередь на актуализацию.
- Каталог доступен без авторизации (для SEO), добавление подписки — после входа.

### FR-05. Трекер триалов · MUST

Отдельная сущность внимания: триал — это подписка с датой автоперехода в платную.

**Критерии приёмки:**
- При добавлении подписки можно указать, что сейчас идёт триал, и дату его окончания.
- Уведомления о триале приходят по отдельному, более настойчивому расписанию (по умолчанию за 3 дня и за 1 день).
- В день окончания триала подписка автоматически переходит в `active` с датой списания = дата окончания триала.
- На дашборде триалы показаны отдельным блоком выше остальных.

### FR-06. Напоминания · MUST

Каналы: *in-app*, Telegram, Web Push, Email. Все четыре — в MVP.

**Критерии приёмки:**
- По умолчанию: одно напоминание за 3 дня до списания. Значение настраивается (1/3/7 дней, можно несколько).
- Пользователь выбирает каналы независимо для каждого типа события.
- In-app лента уведомлений хранит историю за 90 дней и работает всегда, даже если внешние каналы отключены.
- Гарантия отсутствия дублей: одно событие — одно уведомление на канал, даже при повторном запуске планировщика (*идемпотентность*).
- Есть «тихие часы»: уведомления не отправляются с 22:00 до 09:00 по часовому поясу пользователя, а откладываются.
- В каждом внешнем уведомлении есть ссылка на отключение этого типа уведомлений.

### FR-07. Аналитика расходов · MUST

**Критерии приёмки:**
- Расход по месяцам за последние 12 месяцев.
- Разбивка по категориям с долями.
- Прогноз на 12 месяцев вперёд на основе активных подписок.
- Показ «сколько сэкономлено» — сумма отменённых через продукт подписок в годовом выражении.
- Все суммы — в базовой валюте, с явной пометкой, если в расчёте участвовал курс.

### FR-08. Мультивалютность · MUST

**Критерии приёмки:**
- Поддерживаются как минимум RUB, USD, EUR, KZT, BYN.
- Базовая валюта — **настройка пользователя**, меняется в настройках и в онбординге. Валюта новой подписки берётся из неё.
- При первом входе значение **предлагается** по региону устройства: часовой пояс, при неудаче — язык браузера. Доступ к геолокации **не запрашивается**: системный запрос ради выбора валюты несоразмерен (`NFR-04`).
- Если валюта региона не поддерживается (гривна, сум), предлагается USD — валюта, в которой мы не умеем считать, хуже доллара.
- **Определение — только подсказка, и оно ошибается.** Беларусь и Россия в одном часовом поясе UTC+3, а Windows в Минске нередко настроен на московское время: различить их невозможно ни по поясу, ни по языку. Поэтому выбор пользователя сохраняется и никогда не перезаписывается угадыванием.
- Курсы загружаются из источника ЦБ РФ раз в сутки и кэшируются.
- Сумма подписки хранится в исходной валюте. Пересчёт — только на отображении.
- Если курс недоступен, используется последний известный, и интерфейс это показывает.
- Денежные суммы хранятся в *минорных единицах* (копейки, центы) целым числом. Тип `float` для денег запрещён.

### FR-09. Авторизация · MUST

MVP: Telegram Login и Email OTP. Остальные провайдеры — через тот же интерфейс, включаются позже.

**Критерии приёмки:**
- Пароли не хранятся вообще ни в каком виде.
- Один пользователь может привязать несколько способов входа к одному аккаунту.
- Вход через Telegram и последующий вход по тому же email объединяются в один аккаунт после подтверждения владения email.
- OTP-код: 6 цифр, живёт 10 минут, не более 5 попыток ввода, не более 3 запросов кода за 15 минут с одного IP или адреса.
- Сессия живёт 30 дней, продлевается при активности, отзывается при выходе на всех устройствах.

### FR-10. Импорт подписок · SHOULD (расширенный тариф)

Три источника, все — за пределами бесплатного тарифа. Архитектурно единый интерфейс *источника импорта*.

| Источник | Приоритет | Примечание |
| --- | --- | --- |
| Импорт CSV / выписки | SHOULD | Наименьшая юридическая сложность, делаем первым |
| Парсинг почты | COULD | Требует OAuth и ревью restricted scope у почтового провайдера |
| Синхронизация с банком | COULD | Требует юрлица и договора с провайдером агрегации |

**Общие критерии приёмки:**
- Импорт **никогда не создаёт подписки автоматически**. Он формирует список кандидатов, каждый из которых пользователь подтверждает или отклоняет.
- Отклонённый кандидат не предлагается повторно.
- Дубликаты с уже существующими подписками определяются и помечаются.
- Каждый источник требует отдельного явного согласия с описанием, какие данные читаются.
- Отзыв доступа удаляет сохранённые токены источника в течение 24 часов.

### FR-11. Тарифы и фиче-флаги · MUST

Оплата в MVP не подключается, но разделение тарифов существует с первого дня.

**Критерии приёмки:**
- Модель данных содержит тариф пользователя (`free` / `pro`) и таблицу фиче-флагов.
- Доступ к функциям проверяется на сервере, а не только скрытием кнопок в интерфейсе.
- Ограничения бесплатного тарифа: до 10 подписок, ручной ввод, все каналы уведомлений, каталог и гиды.
- Функции `pro`: импорт из любых источников, аналитика глубже 3 месяцев, экспорт данных, неограниченное число подписок.
- Платёжный модуль изолирован за интерфейсом `BillingProvider` с реализацией-заглушкой. Подключение YooKassa не должно затрагивать код вне этого модуля.

### FR-12. Экспорт и удаление данных · MUST

Требование не продуктовое, а юридическое (152-ФЗ).

**Критерии приёмки:**
- Экспорт всех данных пользователя в JSON и CSV по запросу из настроек.
- Полное удаление аккаунта: необратимое стирание персональных данных не позднее 30 дней с момента запроса.
- Удаление доступно самостоятельно из интерфейса, без обращения в поддержку.

### FR-13. Telegram-бот · SHOULD (после веб-версии)

**Критерии приёмки:**
- Канал доставки уведомлений — с первого релиза бота.
- Быстрые действия из уведомления: «оставляю», «отменяю», «напомнить позже».
- Просмотр списка подписок и ближайших списаний текстом.
- Полноценное редактирование — через Mini App, переиспользующий веб-интерфейс.

## Часть II. Нефункциональные требования

### NFR-01. Производительность · MUST
- Дашборд: *LCP* ≤ 1.5 с на профиле «Fast 3G», при 50 подписках.
- Ответ API: p95 ≤ 300 мс, p99 ≤ 800 мс.
- Приложение остаётся работоспособным при 500 подписках у одного пользователя (без деградации до неюзабельного состояния).

### NFR-02. Доступность (a11y) · MUST
- Соответствие WCAG 2.1 уровня AA для основных сценариев.
- Полная работа с клавиатуры на всех формах.
- Контраст текста ≥ 4.5:1; статус подписки не передаётся **только** цветом — всегда дублируется иконкой или текстом.

### NFR-03. Безопасность · MUST
Раскрыто в [06-security-privacy.md](06-security-privacy.md). Кратко:
- Все внешние токены шифруются на уровне приложения перед записью в БД.
- Секреты только в переменных окружения, никогда в репозитории.
- Rate limiting на всех эндпоинтах авторизации и импорта.
- Аудит-лог действий, меняющих состояние подписок.

### NFR-04. Приватность · MUST
- Сбор данных по принципу минимальной достаточности: не собираем то, без чего функция работает.
- Аналитика использования — обезличенная, без сторонних трекеров на клиенте.
- Персональные данные граждан РФ хранятся на серверах в РФ (см. [ADR-0006](adr/ADR-0006-hosting.md)).

### NFR-05. Надёжность · MUST
- Планировщик уведомлений идемпотентен: повторный запуск не создаёт дублей.
- Потеря внешнего канала уведомлений не влияет на работу остальных.
- Недоступность курсов валют не блокирует приложение — работает деградация на последний известный курс.
- Ежедневные автоматические бэкапы БД с проверкой восстановления не реже раза в месяц.

### NFR-06. Наблюдаемость · SHOULD
- Структурированные логи в JSON с идентификатором запроса.
- Метрики: доставленные уведомления, ошибки планировщика, время ответа API.
- Алерт при падении доставки уведомлений ниже 95% за час.

### NFR-07. Локализация · SHOULD
- Все пользовательские строки вынесены в словари, в коде их нет.
- Русский — основной язык; архитектура готова к английскому.
- Даты, числа и валюты форматируются через `Intl`, а не вручную.

### NFR-08. Мобильный опыт · MUST
- Дизайн mobile-first: основной сценарий проектируется под ширину 360 px.
- PWA устанавливается на домашний экран, базовый просмотр работает офлайн.
- Целевые области нажатия ≥ 44×44 px.

## Часть III. Границы версии

| Требование | Статус |
| --- | --- |
| Семейный и общий доступ | `WONT` в MVP → v2 |
| Автоматическая отмена от имени пользователя | `WONT` в MVP → после юридической проверки |
| Виртуальные карты | `WONT` → требует партнёрства с эмитентом |
| Нативные приложения iOS/Android | `WONT` → после подтверждения спроса на PWA |
| Приём платежей | `WONT` в MVP → интерфейс готов, реализация позже |
| Корпоративные аккаунты | `WONT` → другая продуктовая модель |
