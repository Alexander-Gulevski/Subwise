# 06. Безопасность и приватность

> Статус: черновик на согласовании · Обновлён: 2026-07-27
>
> **Дисклеймер:** документ описывает технические меры. Он не является юридическим заключением. Перед публичным запуском требуется консультация юриста по 152-ФЗ и подготовка политики обработки персональных данных.

## 1. Что мы вообще храним

Принцип минимальной достаточности: если функция работает без данных — данные не собираются.

| Данные | Храним? | Зачем |
| --- | --- | --- |
| Email | Да | Вход и уведомления |
| Telegram ID | Да | Вход и уведомления |
| Имя, фамилия, дата рождения | **Нет** | Не нужны ни одной функции |
| Номер телефона | **Нет** | Не используется |
| Пароли | **Нет, никогда** | Их нет в системе в принципе |
| Номера банковских карт | **Нет, никогда** | Только текстовая метка «Тинькофф •4321», введённая вручную |
| Пароли от чужих сервисов | **Нет, никогда** | Прямой запрет — см. раздел 8 |
| Суммы и даты подписок | Да | Это и есть продукт |
| Банковские транзакции | Только при явном подключении | Отдельное согласие, отдельный модуль, `pro` |

## 2. Модель угроз

| # | Угроза | Влияние | Меры |
| --- | --- | --- | --- |
| T1 | Доступ к чужим подпискам через подмену ID | Критическое | Проверка владения в каждой точке входа; чужой ресурс → `NOT_FOUND`, не `FORBIDDEN` |
| T2 | Подделка входа через Telegram | Критическое | Проверка HMAC-SHA256 подписи токеном бота; отклонение данных старше 24 ч |
| T3 | Перебор OTP-кодов | Высокое | 6 цифр, 10 минут, максимум 5 попыток, 3 запроса за 15 мин, счётчики в Redis |
| T4 | Кража токенов импорта из БД | Критическое | Шифрование на уровне приложения перед записью; ключ не в БД |
| T5 | Утечка секретов через репозиторий | Критическое | Только переменные окружения; `.env` в `.gitignore`; сканер секретов в CI |
| T6 | XSS через данные каталога и заметки | Высокое | Экранирование по умолчанию в React; `dangerouslySetInnerHTML` запрещён; CSP |
| T7 | Перехват сессии | Высокое | Cookie `httpOnly`, `Secure`, `SameSite=Lax`; в БД хеш токена, не сам токен |
| T8 | CSRF на мутациях | Среднее | `SameSite=Lax` + встроенная защита Server Actions; вебхуки — по секрету |
| T9 | Вызов cron-эндпоинтов извне | Среднее | Секрет в заголовке, сверка с окружением, 401 без пояснений |
| T10 | Перечисление пользователей через форму входа | Среднее | Ответ одинаков независимо от существования аккаунта |
| T11 | Утечка через логи | Среднее | Запрет логировать токены, коды, тела запросов авторизации |
| T12 | SQL-инъекция | Низкое | Prisma параметризует запросы; `$queryRawUnsafe` запрещён |

## 3. Аутентификация

**Паролей в системе нет.** Это устраняет целый класс рисков: утечку хешей, повторное использование паролей, слабые пароли, атаки на восстановление.

### Email OTP
- Код: 6 цифр, криптостойкий генератор (`crypto.randomInt`, не `Math.random`).
- Время жизни 10 минут, одноразовый, инвалидируется после успешного входа.
- Не более 5 попыток ввода на код, не более 3 запросов за 15 минут на адрес и на IP.
- В базе — хеш кода, не сам код.
- Ответ на запрос кода одинаков для существующего и несуществующего аккаунта.

### Telegram Login
- Обязательная проверка HMAC-SHA256 подписи секретом бота. **Без этой проверки вход подделывается тривиально.**
- Отклонение данных с `auth_date` старше 24 часов — защита от повтора.

### Сессии
- Токен в cookie: `httpOnly`, `Secure`, `SameSite=Lax`, срок 30 дней, скользящее продление.
- В БД хранится SHA-256 хеш токена. Утечка дампа не даёт войти.
- «Выйти на всех устройствах» отзывает все сессии пользователя.

## 4. Шифрование

| Данные | Способ |
| --- | --- |
| Токены источников импорта | AES-256-GCM на уровне приложения перед записью в БД |
| Ключ шифрования | Переменная окружения `ENCRYPTION_KEY`, **никогда в БД и никогда в репозитории** |
| Трафик | HTTPS обязателен, HSTS включён |
| Бэкапы | Шифруются, хранятся отдельно от продакшн-сервера |

Отдельное хранение ключа принципиально: утечка дампа БД без ключа не раскрывает токены.

## 5. Заголовки безопасности

```
Content-Security-Policy: default-src 'self'; img-src 'self' data: https:;
                         script-src 'self'; style-src 'self' 'unsafe-inline';
                         frame-ancestors 'none'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=()
```

`frame-ancestors 'none'` для основного приложения. Для маршрутов Telegram Mini App — отдельная политика, разрешающая домены Telegram.

## 6. Требования 152-ФЗ

| Требование | Как выполняем |
| --- | --- |
| Данные граждан РФ хранятся в РФ | БД и бэкапы на серверах в России. Архитектура на Docker — переезд без изменений в коде ([ADR-0006](adr/ADR-0006-hosting.md)) |
| Согласие на обработку | Явная галочка при регистрации со ссылкой на политику. Отдельное согласие на каждый источник импорта |
| Право на доступ | Экспорт всех данных в JSON и CSV из настроек (`FR-12`) |
| Право на удаление | Самостоятельное удаление аккаунта, полное стирание не позднее 30 дней |
| Уведомление Роскомнадзора | Требуется до начала обработки. Открытый вопрос Q2, к этапу M4 |
| Политика обработки ПДн | Публикуется на сайте, доступна без регистрации |

**Что делает продукт устойчивым:** базовая ценность работает **без** банковских данных. Основной поток — ручной ввод — не создаёт обработки финансовой информации вообще.

## 7. Приватность

- Сторонних трекеров на клиенте нет. Аналитика — собственная, обезличенная.
- Данные пользователей не продаются и не передаются третьим лицам.
- Рекламные профили не строятся.
- Логи не содержат сумм подписок и содержимого заметок.
- Данные удалённых аккаунтов удаляются и из бэкапов при их ротации.

## 8. Красные линии

Правила, которые не обсуждаются и не обходятся ради функциональности:

1. **Не хранить и не запрашивать пароли от чужих сервисов.** Ни «временно», ни «в зашифрованном виде», ни «для удобства пользователя». Это исключает автоматическую отмену через логин — сознательное ограничение, зафиксированное в [ADR-0002](adr/ADR-0002-hybrid-cancellation.md).
2. **Не хранить номера карт и CVV.** Только пользовательская текстовая метка.
3. **Не совершать платежи и переводы** от имени пользователя.
4. **Не создавать подписки автоматически** по данным импорта — только через подтверждение пользователем.
5. **Не утверждать, что подписка отменена**, без явного подтверждения от пользователя.
6. **Не логировать секреты**: токены, OTP-коды, тела запросов авторизации, содержимое `credentialsEnc`.

Нарушение любого пункта — блокирующее замечание на ревью, независимо от того, насколько удобной становится функция.

## 9. Обязательные проверки в CI

| Проверка | Инструмент |
| --- | --- |
| Уязвимости в зависимостях | `npm audit` на каждый PR |
| Секреты в коммитах | Сканер секретов, блокирует merge |
| Типы | `tsc --noEmit`, `strict: true` |
| Правила границ слоёв | `eslint-plugin-boundaries` |
| Изоляция данных пользователей | Обязательный тест на каждый эндпоинт: чужой ресурс → `NOT_FOUND` |
