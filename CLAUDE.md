# Subwise — правила проекта

> Этот файл загружается в контекст автоматически. Он задаёт правила, действующие **всегда**, независимо от задачи.

## Что это за проект

Веб-приложение для управления подписками: собирает все подписки пользователя в одном месте, предупреждает о списаниях и помогает отменить ненужное.

| | |
| --- | --- |
| Техническое имя | `Subwise` — код, репозиторий, пакеты, переменные окружения |
| Публичный бренд (RU) | **«Отписка»** — интерфейс, домен, Telegram-бот, маркетинг |
| Рынок | Россия и СНГ |
| Платформы | Web PWA → Telegram-бот и Mini App |
| Стек | Next.js 15, TypeScript strict, PostgreSQL, Prisma, Redis, BullMQ, Tailwind, Radix |

**Строка «Отписка» не хардкодится в коде** — только в словарях `src/locales/`. Разделение намеренное: код нейтрален к рынку.

## Красные линии

Не обходятся ради удобства функции. Никогда.

1. **Не хранить и не запрашивать пароли от чужих сервисов** — ни в каком виде
2. **Не хранить номера карт и CVV** — только текстовая метка `paymentLabel`
3. **Не совершать платежи** от имени пользователя
4. **Не создавать подписки автоматически** из импорта — только `ImportCandidate` с подтверждением
5. **Не утверждать «отменено»** без явного подтверждения пользователем
6. **Не логировать секреты** — токены, OTP-коды, тела запросов авторизации

Столкнулся с таким требованием — остановись и сообщи.

## Правило зависимостей

```
app / components  →  server  →  domain
                        ↓          ↑
                    adapters  →  ports
```

Обратных стрелок не существует. Проверяется линтером.

| Запрещено | Почему |
| --- | --- |
| `domain/` импортирует Prisma, Next.js, React | Домен обязан тестироваться без инфраструктуры |
| Компонент обращается к Prisma напрямую | Только через `server/` |
| `server/services/` импортирует конкретный адаптер | Только через порт |
| Бизнес-правило в React-компоненте | Не переиспользуется Telegram-ботом |

## Инварианты, которые нельзя нарушать

| Инвариант | Где закреплён |
| --- | --- |
| Статус `cancelled` — только через `CancellationProvider.confirm()` | [ADR-0002](docs/adr/ADR-0002-hybrid-cancellation.md) |
| Деньги — целое `amountMinor`, `float` запрещён | [ADR-0004](docs/adr/ADR-0004-money-currency.md) |
| Конвертация валют — только на отображении | [ADR-0004](docs/adr/ADR-0004-money-currency.md) |
| Даты в БД — UTC, часовой пояс при отображении | [docs/03](docs/03-data-model.md) |
| Импорт создаёт кандидатов, не подписки | `FR-10` |
| Тариф проверяется на сервере | [ADR-0005](docs/adr/ADR-0005-plans-billing.md) |
| Паролей в системе нет | [ADR-0003](docs/adr/ADR-0003-auth.md) |
| Чужой ресурс → `NOT_FOUND`, не `FORBIDDEN` | [docs/04](docs/04-api-contract.md) |

## Обязательный порядок в точке входа

```ts
const data = Schema.parse(input);              // 1. Валидация Zod
const user = await requireUser();              // 2. Аутентификация
await requireOwnership(user.id, data.id);      // 3. Владение ресурсом
await requireFeature(user.id, 'feature.key');  // 4. Тариф, если нужен pro
const result = await service.doWork(data);     // 5. Сервис
await audit.log(...);                          // 6. Аудит при смене состояния
```

**Пропуск шага 3 открывает доступ к чужим данным.** На каждую точку входа обязателен тест изоляции.

## Проверки перед завершением задачи

```bash
npx tsc --noEmit && npx eslint . && npx vitest run
```

- [ ] Тест изоляции данных для каждой новой точки входа
- [ ] Доменная логика покрыта тестами без БД
- [ ] Нет `float` в денежных вычислениях
- [ ] Все четыре состояния экрана: загрузка, пусто, ошибка, норма
- [ ] Доступность: клавиатура, контраст ≥ 4.5:1, статус не только цветом
- [ ] Строки в словарях, не в коде
- [ ] Документация обновлена при изменении контрактов или модели

## Как отвечать

- Есть достаточно информации — действуй, не переспрашивай очевидное.
- Выбор спорный — дай **рекомендацию**, а не обзор вариантов.
- Тест падает — скажи прямо и покажи вывод. Шаг пропущен — скажи, что пропущен.
- Требование неоднозначно — уточни до реализации. Уточнение дешевле переделки.
